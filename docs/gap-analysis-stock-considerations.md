# 股票投資「該考慮但本專案還沒做到」的事 — 缺口盤點

> 盤點基準：`main.py` 每日實際跑的 production 路徑（`evaluate.py` → `backtest.py` → `market.py` / `night_session.py` → `performance.py` → `notify.py`），
> 加上 V3.4 已完成的地基（`context.py` + `factors/`，P1/P2）。
> 標記說明：
> - 🔴 **未規劃** — spec/roadmap 都沒提到，屬於「還沒被想到」的缺口
> - 🟡 **已規劃未實作** — V3.4 P3–P7 或 Roadmap 有寫，但今天跑的系統沒有
> - ⚪ **地基有、決策層沒接** — 資料/因子已經算出來了，但 production 沒用

## 0. 先看這 10 項（會直接改變結論的）

| # | 缺口 | 為什麼致命 |
|---|---|---|
| 1 | **交易成本與證交稅完全沒算** | 台股來回約 0.585%（手續費 0.1425%×2 + 證交稅 0.3%），停利目標只有 10%——成本吃掉近 6% 的名目獲利。回測勝率因此系統性偏高。 |
| 2 | **股價沒有除權息還原** | 除息跳空 -5% 會被指標當成「跌破均線」「觸及停損」；同時 20 日持有期若跨除息，報酬率少算了股利。spec §7 自己把這件事標成 open question，至今未解。 |
| 3 | **回測樣本嚴重重疊** | `backtest.py` 對每個技術分達標的日子都取一次樣，持有 20 日的窗口彼此高度重疊 → 有效樣本遠小於 `samples`。大多頭一段連續訊號就能刷出「勝率 70%」。 |
| 4 | **只有單筆勝率，沒有投組權益曲線** | 沒有最大回撤 / Sharpe / 連續虧損 / 報酬分布。勝率 70% 完全可以配「賺 10% 賠 8%、少數大賠」而總報酬為負。 |
| 5 | **沒有 benchmark** | 沒跟「同期買 0050 抱著」比。多頭期任何策略都賺錢，關鍵是有沒有 alpha。 |
| 6 | **回測勝率直接當 40% 評分權重** | 是「這一檔自己過去 3 年的勝率」，用幾十筆重疊樣本估出來，噪音極大，等於對個股歷史過度配適。而且沒有樣本外/walk-forward。 |
| 7 | **系統只會買、不會賣** | 停損停利只寫在 Telegram 文字裡。隔天沒有任何機制檢查是否觸價，也不會發賣出通知。`Performance` 是紙上追蹤，不是持倉表。 |
| 8 | **沒有投組層概念** | `evaluate.py` 的 `position_size_pct` 在預設停損 8% 下恆為上限 20%；10 檔 BUY = 200% 曝險。沒有總曝險上限、檔數上限、產業集中度控管。 |
| 9 | **不可執行性沒檢查** | 沒有漲跌停鎖死判斷（隔天開盤漲停買不到，回測卻算你買到）、沒有流動性門檻、沒有處置股/全額交割股過濾、沒有最小 1 張的整股換算。 |
| 10 | **production 決策路徑零測試 + CI 不跑 pytest** | 110 個測試全在 V3.4 資料層/因子層；`evaluate.py` / `backtest.py` / `performance.py` / `notify.py` / `night_session.py` 一個測試都沒有。`.github/workflows/` 只有 daily / premarket / telegram smoke。 |

## A. 交易可執行性（假設「能成交」是最大的隱形樂觀）

- 🔴 **手續費／證交稅／滑價** — 全 repo 搜不到 fee / tax / slippage。回測以 T+1 開盤價完美成交。
- 🔴 **漲跌停（±10%）** — 突破訊號隔天常見開盤鎖漲停，中小型股尤其；實際買不到但回測算成本 = 開盤價。
- 🔴 **流動性門檻** — 沒有日均成交金額／週轉率篩選。冷門股 20% 部位進不去也出不來；`volume.py` 只看「相對自己」的量能型態，沒有絕對門檻。
- 🔴 **處置股／警示股／全額交割股／分盤交易** — 處置期間 5 分鐘一次撮合、預收款券，策略假設完全失效。
- 🔴 **停牌／長期無量** — `FactorContext.latest_price()` 會拿停牌前最後一筆當現價，不會標記。
- 🔴 **最小交易單位** — 「建議部位 20%」沒有換算成張數（1000 股），也沒處理零股與整股金額落差。
- 🔴 **除權息還原股價** — 影響 `momentum.*` / `breakout.*` / 停損判定 / 報酬率計算（見上表第 2 項）。
- 🔴 **減資／合併／股票分割** — 股價會被機械式改變，目前無任何 corporate action 處理。

## B. 部位與投資組合（目前只有「個股分數」，沒有「一個帳戶」）

- 🔴 **總曝險上限**：`position_pct = min(2/stop%×100, 20)` 在預設停損下恆為 20，且各檔獨立計算、不相加。
- 🔴 **同時持股檔數上限 / 資金分配演算法**。
- ⚪ **產業集中度與相關性** — `industry` 已抓進 `FactorContext`（`datasources.get_capital_and_industry`），但決策層完全沒用。20 檔 BUY 可能全是 IC 設計，實質是一注。
- 🔴 **現金水位規則** — 空頭時只把 BUY 降為 WATCH，沒有「整體持股水位降到 X%」的量化指令。
- 🔴 **重複訊號冷卻期** — 同一檔可以連續 10 天都 BUY，`performance.py` 只用 `(signal_date, stock_id)` 去重，等於記 10 筆、實務上會不斷加碼同一檔。
- ⚪ **波動度部位縮放** — ATR 已在 `indicators.py` 算出來，但沒用來定 size 或動態停損；固定 8% 停損對高波動股太緊、對低波動股太鬆。
- 🔴 **Kill switch** — 整體回撤或連續虧損超門檻時自動停發訊號。

## C. 出場與持有管理（roadmap 只列了「追蹤停利」）

- 🟡 **已進場部位的每日監控** — 沒有持倉表、沒有觸價檢查、沒有賣出通知。
- 🔴 **實際成交回填 / 現金餘額 / 帳戶淨值曲線** — 無法算真實績效，只有紙上訊號。
- 🔴 **時間停損、移動停利、分批進出**。
- 🔴 **「訊號失效」出場** — 跌破 MA20、法人翻空、月營收轉衰就該走，不必等 -8%。

## D. 基本面深度（production 只有兩個年度數字：EPS、ROE）

- ⚪ **單季／近四季（TTM）EPS** — `context._get_fundamentals_raw` 已產出 `eps_q`，但 `evaluate.py` 用的 `data.get_fundamental` 只有年度值，且要「近 3 年每年達標」→ 結構性排除景氣循環股、轉機股、剛上市的成長股；年報最舊可延遲 15 個月。
- 🔴 **現金流量表** — 營業現金流 vs 淨利（盈餘品質）、自由現金流。EPS 漂亮但收不到現金是台股常見地雷。
- 🔴 **財務結構** — 負債比、流動／速動比、利息保障倍數。
- 🔴 **獲利品質趨勢** — 毛利率／營益率／淨利率的方向（比絕對 ROE 更有訊息量）。
- 🔴 **業外損益佔比** — 一次性處分利益撐出的 EPS 會被當成好公司。
- 🔴 **存貨／應收帳款週轉** — 存貨暴增常是循環股反轉最早的訊號。
- 🔴 **股本變動與稀釋** — 現金增資、可轉債（CB）、員工認股的稀釋與賣壓。
- 🔴 **股利政策** — 連續配息年數、配息率、填息紀錄（`value.high_yield` 只看殖利率的歷史分位）。
- 🔴 **資本效率與其他估值角度** — ROIC、EV/EBITDA、PEG。
- 🔴 **同業／產業相對比較** — 所有估值因子都是「相對自己歷史」；產業整體 de-rating 時完全看不出來。
- 🔴 **公司治理紅旗** — 董監持股與質押比、內部人申報轉讓、會計師更換、財報重編／延遲申報。

## E. 籌碼與市場結構（V3.4 只做了三大法人、融資券、外資持股）

- 🔴 **借券賣出餘額、當沖比率、券資比**。
- 🔴 **集保股權分散表**（千張大戶持股比重變化）。
- 🔴 **券商分點進出**（主力／地緣券商）。
- 🔴 **指數成分調整事件** — MSCI／FTSE、0050／0056 納入剔除帶來的被動買賣盤。
- 🔴 **個股期貨／權證發行量** — 發行商避險賣壓。

## F. 大盤 / 宏觀 / 外部連動

- 🟡 **regime 只有一個二元開關** — `market.py` 僅判「加權指數是否站上 MA20」。沒有波動度 regime、趨勢強度、多／盤／空三態（V3.4 P3 規劃中）。
- 🔴 **美股與費半連動** — 台股電子權重極高，SOX／Nasdaq 隔夜表現對開盤的解釋力高於台指夜盤；`night_session.py` 只抓 TX 期貨。
- 🔴 **匯率、美債殖利率、VIX** — 台幣升貶影響外資流向與出口股毛利；利率環境影響估值。
- 🟡 **真正的類股輪動／相對強弱** — `notify._sector_summary` 用的是 Watchlist 手填的 `category` 欄，而且只在你自己那幾檔之間比較，不是類股指數。Roadmap 列為「規劃中」。
- 🔴 **市場廣度** — 漲跌家數、騰落線（ADL）、市場融資餘額總量、大盤量能萎縮警訊。
- 🔴 **`market.py` 失敗時 fail-open** — 抓不到大盤就回 `bullish=True`（濾鏡不啟用）。風控元件失效時應該 fail-closed。

## G. 事件與行事曆風險（完全沒有 event calendar）

- 🔴 **財報公布日／法說會** — 持有 20 日必然跨財報，卻沒有「財報前不進場」或「財報後重評估」規則。
- 🔴 **月營收公布日（每月 10 日）** — 已知的跳空事件；`datasources.get_month_revenue` 只用它做 point-in-time 切片，沒當成事件用。
- 🔴 **除權息日** — 除了還原股價，「棄息賣壓／填息行情」本身就是可交易的規則。
- 🔴 **股東會停止過戶、增資繳款日、CB 轉換價重設**。
- 🔴 **台股交易日曆** — 全系統用 `datetime.now()` + `timedelta(days=...)` 推日期，沒有真正的交易日曆（連假、補班日、颱風假）。
- 🔴 **連假與政策／選舉事件** 的曝險調整。

## H. 回測方法論（決定「準不準」可不可信）

- 🔴 **樣本重疊 / 自相關** — 見上表第 3 項；應改為不重疊取樣或計算有效樣本數。
- 🟡 **最大回撤 / Sharpe / Sortino / 報酬分布**（V3.4 P3 規劃中，現行 `backtest.py` 只回 winrate / samples / avg_return）。
- 🔴 **benchmark 對照**（買進持有 0050、或同期加權指數報酬）。
- 🟡 **樣本外 / walk-forward** — 參數（EPS>5、ROE>15、技術分 60、總分 65）是人工挑的，卻在同一段資料上評分。
- 🔴 **個股層級過度配適** — 單檔勝率當 40% 權重，改成「同策略跨全市場的勝率」才有統計意義。
- 🟡 **生存者偏誤 + 選擇偏誤** — 現行回測股池就是「你今天 Watchlist 裡還活著的股票」；已下市／爆掉的完全不在樣本內。spec D2 只承諾在 V3.4 用上市／下市日近似。
- 🔴 **多重比較校正** — 掃很多股票 × 很多參數，總會有幾組看起來很強。
- 🟡 **分市況績效** — 沒有分多頭／盤整／空頭看勝率（V3.4 P3）。
- 🔴 **參數敏感度分析** — 停利 10% / 停損 8% / 持有 20 日 這三個數字沒有任何 grid 或穩健性驗證。
- 🔴 **日內順序不可判** — 同一天高低點同時觸及停利與停損時一律算賠（保守但不精確），缺開盤跳空優先或分鐘級處理。
- 🔴 **交易次數／週轉率統計** — 沒有這個就無法估成本侵蝕程度。

## I. 工程與可信度

- 🔴 **production 決策路徑零測試** — `evaluate` / `backtest` / `performance` / `notify` / `night_session` 在 `tests/` 完全搜不到。
- 🔴 **CI 不跑 pytest** — `.github/workflows/` 只有 daily / premarket / telegram-smoke，PR 不會被測試擋下。
- 🔴 **Actions 無快取持久化** — `.cache/finmind` 隨 runner 銷毀，每天冷抓；Watchlist 一大就會撞 FinMind 免費版限流（約 600 req/hr），而 `main.py` 只 `time.sleep(0.6)` 硬跑。
- 🔴 **排程時間風險** — `daily.yml` 台灣時間 14:30 跑，但三大法人買賣超約 15:00–17:00 才更新、盤後定價交易到 14:30；當天籌碼資料很可能還沒到（V3.4 籌碼因子接上 `main.py` 後會更嚴重）。
- 🔴 **資料品質檢核** — 沒有「收盤價是否為 0 / 是否異常跳空 / 資料是否延遲一天」的 sanity check；`evaluate.py` 只在 <100 列時 SKIP。
- 🔴 **單一資料源** — 完全綁 FinMind，掛了整條停，無降級或第二來源。
- 🔴 **錯誤被吞成中性** — `registry` 的 `except → NEUTRAL(0.5)`、`evaluate` 的 `except → ERROR`、`market` 的 `except → bullish=True`。分數看起來正常，實際是資料掛了。
- 🔴 **無 audit trail** — Signals 沒記下當天用的策略版本／程式 commit，事後無法歸因「當時為什麼買」。

## J. 選股漏斗與使用者流程

- 🔴 **股池必須手動維護** — 系統只評 Watchlist 裡已有的股票，從不掃全市場（約 1800 檔）找新標的。真正「選股」缺了漏斗最上層。
- 🔴 **無橫斷面排名** — 只有絕對分數門檻，沒有「今天全市場前 20 名」的相對排序，也就無法回答「為什麼買這檔而不是那檔」。
- 🔴 **Performance 報酬是毛的** — 沒有扣成本／稅後的淨績效。
- 🟡 **週報／月報與績效歸因**（Roadmap 規劃中）。
- 🟡 **what-if 參數比較介面**（Roadmap 規劃中）。

## 建議的補洞順序

1. **先讓數字可信**：交易成本 + 稅 → 除權息還原 → 樣本不重疊 → 加 benchmark 與最大回撤。這四件事做完，現有「勝率」的解讀會完全不同，而且不需要新資料源。
2. **再讓訊號可執行**：流動性門檻 + 漲跌停/處置股過濾 + 整股換算。
3. **接著補投組層**：總曝險上限、檔數上限、產業集中度、重複訊號冷卻。
4. **然後把賣出補上**：持倉表 + 每日觸價監控 + 賣出通知。
5. **最後才擴資料維度**：現金流／財務結構／事件行事曆／美股連動。

> 註：第 1、3、4 項幾乎都不需要新的外部資料，是投入產出比最高的部分。
